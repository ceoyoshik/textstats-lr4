## BUG-1. Предложение без пробела после точки не распознаётся

| Поле | Значение |
| --- | --- |
| ID | BUG-1 |
| Компонент | `src/processing_module.py`, `split_sentences` |
| Найден | `test_split_sentences_without_space_after_dot` |
| Тяжесть | Major |
| Приоритет | High |
| Статус | Исправлен |

**Описание.** Регулярное выражение требовало пробел или конец строки
после знака конца предложения. Текст «Привет.Как дела?» (точка без
пробела — типичная ошибка набора, копирование из PDF) считался одним
предложением, поэтому показатель «Предложений» был занижен.

**Шаги воспроизведения.**

1. Вызвать `split_sentences("Привет.Как дела?")`.

**Ожидаемое поведение.** Два предложения.

**Фактическое поведение.** Одно предложение (разделитель не найден).

**Исправление.** Разделитель `[.!?…]+` без требования пробела; пустые
части отбрасываются. Тест: `test_split_sentences_without_space_after_dot`,
регрессионный сценарий «два предложения».

## BUG-2. Управляющие символы проходят через протокол обмена

| Поле | Значение |
| --- | --- |
| ID | BUG-2 |
| Компонент | `src/protocol.py`, `parse_request` |
| Найден | `test_parse_request_rejects_control_symbols` |
| Тяжесть | Major |
| Приоритет | High |
| Статус | Исправлен |

**Описание.** Модуль ввода отклонял управляющие символы (кроме `\n`, `\r`,
`\t`), а граница протокола — нет. Сообщение `text_request` с символом
`\x00` внутри принималось, статистика считалась по испорченному тексту,
и расхождение проявлялось только при сравнении с прямым вводом.

**Шаги воспроизведения.**

1. Собрать `text_request` с `text = "текст\x00с нулём"`.
2. Вызвать `protocol.parse_request(message)`.

**Ожидаемое поведение.** `InputDataError` — те же правила, что и при
консольном вводе.

**Фактическое поведение.** Текст принимался без ошибки.

**Исправление.** Общая проверка `protocol.check_text_symbols()` вызывается
и в модуле ввода, и в `parse_request`. Тесты:
`test_parse_request_rejects_control_symbols`,
`test_parse_text_rejects_control_symbols`.

## BUG-3. Частота слова может превышать число слов в тексте

| Поле | Значение |
| --- | --- |
| ID | BUG-3 |
| Компонент | `src/protocol.py`, `parse_response` |
| Найден | `test_parse_response_rejects_frequency_above_word_count` |
| Тяжесть | Minor |
| Приоритет | Normal |
| Статус | Исправлен |

**Описание.** При разборе `stats_response` проверялись типы элементов
`top_words`, но не согласованность: ответ с `words = 1` и
`top_words = [["слово", 5]]` принимался, хотя частота не может превышать
общее число слов. Ошибка в модуле обработки осталась бы незамеченной.

**Шаги воспроизведения.**

1. Собрать `stats_response`, где `words = 1`, `top_words = [["слово", 5]]`.
2. Вызвать `protocol.parse_response(message)`.

**Ожидаемое поведение.** `ProtocolError`.

**Фактическое поведение.** Ответ принимался, частота `5` попадала в отчёт.

**Исправление.** Проверка `count <= words` для каждого элемента; тест
`test_parse_response_rejects_frequency_above_word_count`.
