# Архитектура и протокол обмена

## 1. Модульная структура

| Модуль | Вход | Выход | Ответственность |
| --- | --- | --- | --- |
| `input_module` | файл или stdin | `str` | чтение, проверка размера, пустоты, управляющих символов |
| `processing_module` | `text_request` | `stats_response` | токенизация, предложения, частоты, статистика |
| `output_module` | `TextStats` | текст отчёта | форматирование, округление, отрицательный ноль |
| `protocol` | словарь Python | JSON-файл | конверт, версии, валидация, атомарная запись |
| `mapping` | структуры модулей | структуры протокола | `TextStats` ↔ JSON |
| `textstat` | аргументы CLI | код завершения | подпроцесс, повторы, тайм-аут |

## 2. Формат сообщений

```
{"version": "1.0", "type": "text_request", "payload": {"text": "..."}}
```

```
{"version": "1.0", "type": "stats_response",
 "payload": {"chars": 24, "chars_no_spaces": 20, "words": 4,
             "sentences": 2, "unique_words": 3, "avg_word_length": 4.5,
             "longest_word": "Привет",
             "top_words": [["мир", 2], ["привет", 1]]}}
```

```
{"version": "1.0", "type": "error",
 "payload": {"code": "invalid_data", "message": "..."}}
```

Коды ошибок: `invalid_data`, `protocol_error`, `version_conflict`.

## 3. Таблица сопоставления данных

| Модуль | Поле модуля | Поле протокола | Преобразование |
| --- | --- | --- | --- |
| ввод | `str` | `payload.text` | без изменений |
| обработка | `TextStats.chars` | `payload.chars` | `int` |
| обработка | `TextStats.top_words` | `payload.top_words` | кортеж → список пар |
| вывод | `TextStats` | — | `tuple(top_words)` при разборе |

## 4. Правила обработки текста

1. Слово — последовательность букв, цифр, дефисов и апострофов внутри
   слова (`мама-мама`, `don't`, `2026`).
2. Предложение завершается одним или несколькими знаками `.!?…`; пробел
   после знака не обязателен.
3. Частоты считаются без учёта регистра; сортировка — по убыванию
   частоты, при равенстве — по алфавиту.
4. Средняя длина слова округляется до двух знаков.
5. Пустой или пробельный текст — ошибка `invalid_data`.

## 5. Коды завершения

| Код | Значение |
| --- | --- |
| 0 | успех |
| 1 | ошибка данных (ввод или содержимое сообщения) |
| 2 | ошибка интеграции (подпроцесс, тайм-аут) |
| 10 | в файл ответа записано сообщение `error` (внутренний код модуля обработки) |
| 3 | модуль обработки не смог записать ответ |

## 6. Устойчивость

- запись файлов обмена атомарна (`os.replace`);
- подпроцесс ограничен тайм-аутом (по умолчанию 10 с);
- при сбое модуля обработки выполняется до двух попыток;
- устаревший `response.json` удаляется перед каждым запуском;
- сообщение `error` от модуля обработки превращается в исключение
  соответствующего типа.
